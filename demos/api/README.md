# REST API на Go и Python: один контракт, одинаковые ответы

Демо: **https://api.demo.sedlab.dev**

Серверная часть для небольшой компании: клиенты, заказы со статусами, фоновые задачи. Описание API (OpenAPI) написано
один раз, а по нему сделаны две реализации: на Go и на Python (FastAPI). Обе работают с одной базой и проходят один и тот же
набор автоматических проверок, поэтому отвечают одинаково. На странице демо можно переключать Go и Python и сравнить ответы.

## Что можно потрогать
- **Swagger**: все методы с описанием, кнопка «Try it out». Сервер в Swagger следует за переключателем Go / Python.
- **Токен песочницы** одной кнопкой: у каждого посетителя своя база с тестовыми клиентами и заказами, Swagger авторизуется сам.
- **Вход через аккаунт** (Max, Яндекс ID, VK ID): сервис входа выдаёт сессию, API меняет её на свой токен,
  рабочее пространство закрепляется за аккаунтом.
- **«Сравнить ответы»**: одни и те же запросы уходят в обе реализации, видно коды ответов, время и совпадение JSON.
- **Фоновые задачи**: «выставить счёт», «синхронизация с CRM» с двумя сбоями, «уведомление», которое не проходит никогда.
  Видно, какой воркер (Go или Python) взял каждую попытку, как идут повторы через 1, 2, 4 секунды и как задача после
  4 неудач уходит в «dead».

## Что умеет API
| | |
|---|---|
| Авторизация | токен (JWT), срок 24 часа; вход через внешний сервис аккаунтов; у каждого рабочего пространства свои данные |
| CRUD | клиенты и заказы: создание, чтение, частичное изменение, удаление с проверкой связей |
| Бизнес-правила | статусы заказа: новый → подтверждён → в работе → выполнен, отмена из любого незавершённого; запрещённый переход даёт понятную ошибку |
| Списки | фильтры (статус, клиент, метка, поиск по тексту, даты, сумма), сортировка, постраничный вывод курсором и общее число записей |
| Ошибки | единый формат: код, сообщение и список всех неверных полей сразу |
| Повтор запроса | заголовок `Idempotency-Key`: повтор не создаст второй заказ (важно для оплаты и плохой связи) |
| Фоновые задачи | очередь в базе, ретраи с нарастающей паузой, «мёртвые» задачи, история попыток; очередь разбирают оба бэкенда, без двойной обработки |
| Защита | лимит запросов, лимит размера тела, квоты на объём данных, автоочистка песочниц |
| Миграции | нумерованные SQL-файлы, общие для обеих реализаций; применяются при старте ровно один раз |
| Документация | OpenAPI 3.1 и Swagger UI, правила поведения в `contract/BEHAVIOR.md` |
| Тесты | один набор контрактных тестов (более 80 проверок) гоняется против Go, против Python и против обеих сразу (сравнение ответов); браузерный e2e страницы |
| Запуск | один Docker-образ, `docker compose up`, HTTPS через Caddy, сервер в России |

## Стек
Go 1.23 (стандартная библиотека net/http, SQLite без CGO) · Python 3.12, FastAPI, uvicorn · SQLite (WAL) ·
OpenAPI 3.1, Swagger UI · pytest + jsonschema (проверка ответов по контракту) · Playwright · Docker, GitHub Actions, Caddy.

База в демо: SQLite, чтобы уложиться в 150 МБ памяти на обе реализации. Для проекта с большой нагрузкой та же схема
переносится на PostgreSQL.

## Сколько стоит и сколько занимает
Ориентир по ценам кворка «Серверная часть (API)»:
- API до 5 функций (вход, данные, 2-3 бизнес-операции), документация, проверки, запуск в Docker: **от 5 000 ₽, 3 дня**;
- API уровня этого демо (около 15 функций, фоновые задачи, размещение на сервере):
  5 000 + 2 × 3 000 + 3 000 + 2 500 = **около 16 500 ₽**, 5-7 дней;
- вторая реализация на другом языке по тому же контракту, перенос на PostgreSQL, панель управления: по договорённости.

Сначала согласуем описание API (какие методы, поля и ошибки), потом пишу код. Фронтенд и мобильное приложение
можно делать параллельно по тому же описанию.

## Как устроено
```
contract/openapi.yaml   описание API (источник правды)       contract/BEHAVIOR.md  правила, одинаковые для обеих реализаций
contract/seed.json      тестовые данные новой песочницы      migrations/*.sql      миграции (общие)
go/                     реализация на Go                     python/api_py/        реализация на Python (FastAPI)
tests/contract/         контрактные тесты (одни на обе)      tests/run.sh          поднять обе и прогнать тесты
web/                    страница демо и Swagger              e2e/                  браузерный сценарий, скриншоты и видео
```
Один образ запускается двумя процессами: Go отдаёт страницу, `/go/*` и `/v1/*`, Python отвечает на `/py/*`.
Оба работают с одной базой SQLite и одной очередью задач.

## Запуск локально
```bash
ln -s <путь к sedlab-modules> .modules-src                     # приватный модуль accounts (вход через аккаунт)
(cd python && python3 -m venv .venv && .venv/bin/pip install ../.modules-src/modules/accounts/python -e '.[test]')
tools/dev.sh ru                                                 # http://127.0.0.1:18080
tests/run.sh ru && tests/run.sh intl                            # контрактные тесты: Go, Python, сравнение
(cd e2e && npm i && node e2e.mjs)                               # браузерный сценарий (стенд должен быть запущен)
```

Данные в песочницах тестовые и удаляются каждый день, а также после 12 часов без запросов. Не вводите реальные данные.
